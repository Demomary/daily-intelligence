## 1. DPDK 26.11.0 正式发布并列为 LTS：高性能网络框架迎来一轮重要 API 清理

**发布日期：2026-11-26。**  
**分类：非 AI 开源项目 / 高性能网络与数据平面。**

DPDK 官方下载页已将 26.11.0 列为最新版本和最新长期支持版本（LTS），发布日期为 11 月 26 日。此前 11 月 26 日简报中仍只能确认 rc4；本次已核对官方发布页，状态发生了实质变化。

### 主要变化

- 新增 pile：面向批量操作的无锁栈式数据结构及 mempool driver。注意它是按 bulk 组织的 LIFO，不等同于对象级严格栈。
- 新增 VFIO cdev / IOMMUFD 模式，与原有 VFIO group 模式并存。
- ethdev 增加 1.6 Tb/s 链路速率表示能力，可描述例如两个 800 Gb/s 成员组成的聚合链路。
- 新增可插拔模块 EEPROM 解码 API；同时增加 BPF 预验证工具和基于 Google Wycheproof 测试向量的 cryptodev 验证应用。
- 更新多个 PMD，包括 NXP ENETC4、ZTE zxdh、Intel QAT 等。

### 对现有工程影响更大的，是 API 移除

| 移除/变化 | 迁移方向 |
|---|---|
| rte_atomicNN_t 及 rte_atomicNN_* | 使用 C11 风格的 rte_atomic_*_explicit 操作 |
| rte_smp_mb/rmb/wmb | 按 acquire/release/seq_cst 语义改用 rte_atomic_thread_fence；CPU 与设备访问排序需区分，设备侧使用 rte_io_wmb/rmb |
| 旧 rte_pipeline_*/rte_table_*/rte_port_* API | 迁移到 SWX API；旧 pipeline 测试程序及 ip_pipeline 示例也已移除 |
| vhost 实验性异步 DMA 数据路径 | 相关异步 API 和 RTE_VHOST_USER_ASYNC_COPY 标志已移除 |
| 公共 VFIO rte_vfio_* API | 已转为 EAL/driver 内部 API |

**为什么值得关注：** 这不是单纯增加几个网卡驱动，而是一次需要认真评估兼容性的版本升级。对使用 DPDK 23.x 的工程，跨越多个版本直接升级到 26.11，不能只以“能否编译通过”作为验收标准，尤其要核对原子操作和屏障的语义。

结合多核收发、mbuf 生命周期、跨核队列和设备 DMA 场景，建议先做 API 静态扫描，再逐项核对 acquire/release、线程间可见性以及 CPU—设备内存排序。若应用使用的是 GCC/Clang 的 __sync_* 内建函数，DPDK 移除 rte_atomicNN_* 并不等于这些编译器内建函数也被移除；但仍应独立审查其内存序语义。

## 2. 星动纪元 45 台具身机器人进入中国邮政杭州邮区中心，承担小件供包

**发布日期：2026-11-25 至 2026-11-26。**  
**分类：具身智能 / 机器人实际部署 / 物流自动化。**

中国邮政杭州分公司联合北京星动纪元与我能具身（深圳），在杭州邮区中心部署 45 台星动M7具身机器人，承担小件供包环节。机器人需要从随机堆放的包裹中抓取、翻面、识别异形件、剔除不适合上件的包裹，再将合格包裹放到供包台，接入原有自动分拣线。

### 这次值得关注的不是“人形”称呼，而是具体工序和部署数量

~~~mermaid

    B --> C["翻面 / 姿态调整"]
    C --> D{"是否适合供包？"}
    D -->|是| E["放置到供包台"]
    D -->|否| F["异形件剔除 / 异常处理"]

    F --> H["人工或其他流程兜底"]
~~~

公开报道给出的效率数据并不完全一致：

- 星动纪元通过 PR Newswire 发布的新闻稿称，项目测试开始于 2026 年 4 月，初期约 500–600 件/小时，在特定测试时段达到约 1,200 件/小时，作业准确率超过 90%。
- 杭州政府英文站转述 Global Times 对企业官方微信的报道，以及 11 月 25 日的中文行业报道，则称该杭州项目在 8 月底至 9 月初完成部署投测，初始约 1,200 件/小时，现场已超过 1,500 件/小时。

**这些数字均来自企业披露或媒体转述，尚未见到中国邮政公开的独立验收报告、长时间连续运行记录或第三方审计。** 因此本期不把 1,200 或 1,500 件/小时写成经过独立验证的稳定平均产能，也不将“准确率超过 90%”扩展为整条分拣线的准确率。

**部署成熟度判断：** 这是有明确客户、明确地点、明确工序和 45 台设备数量的真实现场部署/测试，证据强于单机展台演示；但公开资料尚未给出设备利用率、故障停机时间、人工介入比例、单件成本和完整班次产能。M7承担的是供包这一前置工序，不等于整座邮区中心已无人化，也不等于通用双足机器人已经替代完整物流分拣系统。

**为什么值得关注：** 物流供包是自动分拣线前端的柔性环节，包裹形状、尺寸和朝向不固定，传统固定机构较难覆盖。机器人与原有扫码、分拣设备及 AGV 协同，比“机器人独立完成整座仓库作业”更接近可落地的工业方案。下一步真正值得跟踪的是跨站点复制、连续运行可靠性和每件包裹的综合成本。

## 3. 东京核心 CPI 同比升至 2.9%，为 16 个月最快，日银 12 月加息预期增强

**发布日期：2026-11-27。**  
**分类：日本经济 / 通胀与货币政策。**

日本总务省公布的东京区部 11 月 CPI 初值显示：

| 指标 | 2026年10月 | 2026年11月 |
|---|---:|---:|
| 核心 CPI 同比（剔除生鲜食品，包含能源） | 2.6% | 2.9% |
| 核心核心 CPI 同比（剔除生鲜食品及能源） | 2.6% | 2.5% |

东京核心 CPI 同比升至 2.9%，为 2025 年 7 月以来最快，连续第三个月高于日本央行 2% 的目标。11 月数据略低于市场预期的 3.0%。推动因素包括政府水电燃气补贴结束，以及食品、日用品和酒店价格上涨。剔除生鲜食品和能源后的指标则从 2.6% 小幅回落到 2.5%，说明不同价格分项并非同步加速。

**为什么值得关注：** 东京数据通常被视为全国通胀趋势的先行指标。核心 CPI 加速会增强日本央行在 12 月 17–18 日会议上继续加息的理由；但剔除食品和能源后的指标略有回落，且金融市场波动可能影响决策。加息仍是市场预期，不是已经作出的政策决定。

## 4. ASEAN+3 同意成立跨境数字支付工作组，中国、日本、韩国与东盟推进支付互联

**发布日期：2026-11-26。**  
**分类：中国与日本 / 区域金融合作 / 数字支付。**

11 月 25–26 日，东盟与中日韩（ASEAN+3）财金副手会议在日本京都举行。各方同意建立 AMRO（东盟与中日韩宏观经济研究办公室）的跨境数字支付新项目及专门工作组，研究如何加强各国本土支付系统之间的跨境连接，并协调数字资产相关监管措施。

日本财务省公布的会议结果还包括：修订后的清迈倡议多边化（CMIM）协议生效，并引入快速融资机制（Rapid Financing Facility）；该区域货币互换安全网规模为 2,400 亿美元。

**为什么值得关注：** 中国、日本、韩国和东盟的贸易、旅游与供应链联系紧密。若未来能够减少本土支付系统之间的连接障碍，可能降低跨境小额支付的摩擦，并推动区域数字金融规则协调。

**目前的边界：** 这次确定的是研究项目和工作组，不是已经建成一个统一支付网络；官方尚未公布参与支付系统名单、技术标准、结算货币、费用安排或具体上线时间。不要将其理解为数字人民币或任何单一支付工具已在整个东盟+3地区互通。

## 5. 多国回应美国新的关税提案：中国称将采取必要措施，日本提出抗议

**发布日期：2026-11-26。**  
**分类：国际贸易 / 中国、日本与美国。**

这是 11 月 26 日简报中美国 Section 301 关税提案的后续，不重复提案本身，只记录本周期新增回应：

- 中国外交部表示反对将所谓“产能过剩”作为贸易限制借口，并称将采取必要措施维护自身合法权益。
- 日本政府向美方表达抗议，称日本不存在扭曲全球市场的结构性产能过剩。
- 新加坡、马来西亚和欧盟也反对美国的相关认定；越南表示仍在与美国谈判。
- AP 报道称，相关措施预计要到 2027 年初才可能实施。分析人士认为，部分拟议税率可能替代此前的关税安排，但仍可能使美国核心商品通胀在明年保持较高水平。
